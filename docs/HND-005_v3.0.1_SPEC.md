# HND-005 v3.0.1 Spec

## Purpose

`HND-005` applies the shipped handoff schema to the handoff document.
It answers:

> Does this handoff satisfy the contract the repository publishes for it?

`HND-002` checks the shape by hand: required fields, known states, valid trust
tiers, a matching hash. That set was always a subset of what
`schemas/mica.handoff.schema.json` states, and the difference was not enforced. A
handoff declaring `project_scope: ""` passed every hand-written check and
reached agent context, while the schema rejects it.

Publishing a schema and not applying it is worse than publishing none, because
the schema reads as the contract to anyone who finds it.

## Scope

Applies whenever a handoff document is present and parseable, so it runs after
`HND-001` and alongside `HND-002`.

## Inputs

- `memory/mica_handoff.json` (or wherever `find_flow_artifact` resolves it)
- `schemas/mica.handoff.schema.json`

## Minimum PASS conditions

- the document validates against the shipped schema with no errors

## FAIL conditions

- the schema rejects the document, for any reason the schema states
- the schema file is missing or unreadable

## SKIP condition

`jsonschema` is not installed.

`tools/` is vendored by consumer packages, so the validator cannot be a hard
runtime dependency. Its absence is reported as `SKIP` with the reason, never as
`PASS`: a check that silently passes when it did not run is worse than one that
says it could not run.

## Consequence

A `FAIL` here makes the handoff undeliverable. `handoff_is_deliverable()` in
`mica_core` treats `HND-005` like `HND-002`, so the surface is withheld from
agent context and `PCT-007` reports the contract as incomplete when a profile
named it.

## Why it is not folded into HND-002

`HND-002` answers "can this be read as a handoff at all", and its failures are
phrased for a human fixing a document by hand. `HND-005` answers "does it match
the published contract", and its failures are the schema's own wording. Merging
them would make one message mean two things, and would hide which of the two
sources rejected the document.

## History

Added in `v3.0.1`, from the second invocation-truth audit. The counter-example
was reproduced before the fix: a handoff with an empty `project_scope`, one
schema error, every `HND` check passing, and the surface delivered.
