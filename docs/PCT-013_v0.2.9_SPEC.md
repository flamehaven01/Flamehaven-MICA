# PCT-013 v0.2.9 Spec

## Purpose

`PCT-013` is the first static flow-plane gate.
It answers one question:

> If flow is enabled, is the observation stream present, parseable, and internally coherent enough
> to support later promotion decisions?

This is not a retrieval-quality check.
It is an evidence-integrity check.

## Scope

Applies only when:

- `flow_policy.enabled=true`

Returns `N/A` or `INFO` when flow is not enabled.

## Inputs

- `mica.yaml`
- `memory/mica.observe.jsonl`
- `mica.observe.schema.json` or in-code equivalent validator rules

## Minimum PASS conditions

- observation file exists
- every line parses as valid JSON
- every line declares supported `schema_version`
- every record has mandatory identity fields
- `event_hash` recomputes from the normalized record payload
- `prev_event_hash` links are coherent within the validated segment
- no duplicate `event_id`
- stream ordering is deterministic inside the validated segment

## WARN conditions

- timestamp monotonicity breaks, but hash-link order remains coherent
- optional metadata is absent while integrity-critical fields remain valid

WARN may be useful for operator attention, but must not hide structural corruption.

## FAIL conditions

- flow enabled but `mica.observe.jsonl` missing
- any line fails JSON parse
- unsupported `schema_version`
- duplicate `event_id`
- missing mandatory identity or integrity fields
- recomputed `event_hash` does not match stored `event_hash`
- `prev_event_hash` pointer breaks within the validated segment
- stream ordering cannot be reconstructed deterministically

## Notes

- Redaction may change payload-bearing fields, but must not break identity fields used by this check.
- First-record handling is segment-aware: a segment head may omit `prev_event_hash`.
- Timestamp ordering is weaker than hash-chain ordering; the latter is authoritative for PASS/FAIL.
