# PCT-014 v0.2.9 Spec

## Purpose

`PCT-014` is the first recall-trace coverage check.
It answers:

> If recall is active, does MICA have enough runtime trace to audit where recalled candidates were surfaced?

This is a telemetry-integrity check, not a promotion hard gate.

## Scope

Applies when:

- `flow_policy.enabled=true`
- recall is active or a recall trace file is present

## Inputs

- `mica.yaml`
- `mica.recall.jsonl`
- `mica.candidates.json`

## PASS conditions

- recall trace file exists when recall is active
- every trace record declares supported `schema_version`
- every trace record declares `target`
- every trace record declares `candidate_id`
- trace records carry enough session identity to audit where recall surfaced

## WARN conditions

- recall is enabled but `mica.recall.jsonl` is missing
- recall trace exists but is empty during active recall
- recall trace contains unsupported `schema_version`
- recall trace records omit `target`, `candidate_id`, `recall_id`, or `session_id`

## Notes

- `PCT-014` is intentionally non-blocking for Core package truth in v0.2.9.
- A `WARN` here should still degrade Flow reporting because runtime auditability is incomplete.
- `PCT-017` remains the hard safety gate for forbidden `agent_context` injection.
