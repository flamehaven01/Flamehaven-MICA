# PCT-018 v0.2.9 Spec

## Purpose

`PCT-018` checks whether enabled flow telemetry is joinable across runtime surfaces.
It answers:

> When recall traces exist, can MICA connect them back to both the candidate registry and the observation stream?

This is a non-blocking telemetry-integrity signal.

## Scope

Applies when:

- `flow_policy.enabled=true`
- `mica.recall.jsonl` exists

## PASS conditions

- each recall record references a candidate that exists in `mica.candidates.json`
- each recall record carries `source_event_ids`
- each recall record links to a `session_id` present in the observation stream
- each recall record's `source_event_ids` resolve in `mica.observe.jsonl`
- each recall record's `source_event_ids` remain consistent with the candidate's `source_event_ids`

## WARN conditions

- recall trace exists but cannot be joined to candidate registry
- recall trace exists but omits `source_event_ids`
- recall trace session identity cannot be linked back to observed sessions
- recall trace cites source events that do not exist in the observation stream
- recall trace cites source events not declared on the referenced candidate

## Notes

- `PCT-018` does not close the package; it degrades Flow reporting only.
- `PCT-014` asks whether trace coverage exists at all.
- `PCT-018` asks whether the available trace is complete enough to replay causality cleanly.
