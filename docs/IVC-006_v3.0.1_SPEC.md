# IVC-006 v3.0.1 Spec

## Purpose

`IVC-006` applies the shipped invocation schema to every record in a trace.
It answers:

> Does each recorded capsule satisfy the contract the repository publishes for it?

`IVC-000` reported that `schemas/mica.invocation.schema.json` exists. Nothing validated
against it. `IVC-003` and `IVC-004` hand-check a field list and cross-field
coherence, so anything the schema forbade but those two did not mention passed:
a trace carrying an unknown field was reported `VALID INVOCATION TRACE` with
exit 0.

A trace is provenance. A record that does not match the published shape is not
a truthful account of a session, whatever else it contains.

## Scope

Runs after `IVC-002` has parsed the trace, over every record it parsed. A trace
is judged by its worst record: one invalid capsule fails the check.

## Inputs

- the invocation trace (`memory/mica.invocation.jsonl` by default)
- `schemas/mica.invocation.schema.json`

## Minimum PASS conditions

- every record validates against the shipped schema with no errors

## FAIL conditions

- any record is rejected by the schema
- the schema file is missing or unreadable

The message names the record's position in the file and the first errors, so a
long trace does not have to be bisected by hand.

## SKIP condition

`jsonschema` is not installed. Same reasoning as `HND-005`: `tools/` is vendored,
the validator cannot be a hard dependency, and a check that did not run must say
so rather than pass.

## Relationship to the writer

`write_invocation_trace()` runs this schema check, plus `_check_capsule_schema`
and `_check_capsule_coherence`, before appending. A record that would fail
`IVC-006` is never written.

The schema alone is not sufficient there: two roles pointing at one file is
valid JSON and an incoherent capsule, caught by `IVC-003` rather than by the
schema. The writer runs both for that reason.

## History

Added in `v3.0.1`, from the second invocation-truth audit. The counter-example
was reproduced before the fix: a capsule with an added field, rehashed so the
capsule hash still verified, reported `VALID` with exit 0.
